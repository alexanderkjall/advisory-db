# Unsoundness in alloc-no-stdlib

The alloc_cell function in alloc-no-stdlib makes a call to std::vec::Vec::set_len
without initializing the values from 0 to len first. This breaks the unsafe contract
that set_len stipulates, that it's only safe to call if the following criteria are met:

- new_len must be less than or equal to capacity().
- The elements at old_len..new_len must be initialized.

See https://doc.rust-lang.org/std/vec/struct.Vec.html#method.set_len for reference.

The following program demonstrates the undefined behaviour:

```
#![feature(never_type)]

use alloc_stdlib::HeapPrealloc;
use alloc_stdlib::Allocator;
use alloc_no_stdlib::{uninitialized};

fn main() {
    let mut heap_global_buffer = unsafe{HeapPrealloc::<!>::new_uninitialized_memory_pool(1)};
    let mut ags = HeapPrealloc::<!>::new_allocator(1, &mut heap_global_buffer, uninitialized);

    let x = ags.alloc_cell(1);
    println!("{}", x[0]);
}
```
